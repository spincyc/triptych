# Limitations — what this package does not prove

### 1. The scope is one correction, and the head is not a candidate for acceptance

This head closes the composed prefix/fallback escape the V8 review found,
and corrects the package pipeline's final-byte truthfulness — and nothing
else. `UNRESOLVED-BLOCKERS.md` lists what stays open. A review of this
package can accept the composed closure at most; it cannot accept E1, and
the package claims nothing wider.

### 2. The sink proved is the harness's fetch seam

The request journals come from the replay harness's stubbed `fetch` — the
same seam, driven the same way, that the V7 and V8 reviews used to prove
their defects. The prewarmed and genuinely late scenarios exercise the
production path-keyed body cache and the real deferred completion through
that same seam. That is a claim about which addresses the production files
hand to the network boundary and when; it is not a network capture from a
real browser session. The browser gate did run in real Chromium at both
ends, over the built site, but it asserts the shared shell's generic
contract, not this route's request journal.

### 3. No screenshots, and no route-specific Chromium probe

The stylesheet, the markup and the page script are byte-identical to the
parent and the change is semantic; a raster of a valid chapter would be
identical at both ends. `logs/derive-claims.py` counts image pairs from the
sealed directory and reports the count derived rather than an absence
described. What replaces a probe is the head test file replayed against the
parent's production files (`logs/v8-tests-against-parent.log`) and the two
request journals side by side.

### 4. The refusal's page-level sentence is shared, deliberately

A refused prefix and a genuinely absent text file print the same terminal
sentence; the distinction lives on the projected row as `text_refused`,
which the untouched page does not yet consume. The correction brief
authorized the existing truthful terminal state; `REVIEW_REQUEST.md` §2
asks whether the next lane should spend `src/web/browser/catena/catena.js` bytes on a distinct
sentence.

### 5. The parent-side battery baselines are inherited, not adjudicated

Full discovery, the make targets and the browser gate fail at the parent
and at the head in the same inherited identities; the package proves the
sets match, not that the sets are acceptable. They belong to their separate
owners.

### 6. The V9 classes' parent decomposition includes an infrastructure fault

The head's test file pins the model by digest, so at the parent it fails
the byte-identity guard as well as the composed-closure classes. The
per-class decomposition in `DERIVED-CLAIMS.md` is derived from the log
rather than asserted, so the reader can separate the guard's expected
failure from the classes that state the defect.

### 7. Judgements are not derivations

Every figure a machine could derive is derived into `claims.json`. Whether
property presence is the right definition of absence, whether the shared
terminal sentence is truthful enough, whether derived members belong inside
the archive, and whether the model needs a ceiling are judgements;
`REVIEW_REQUEST.md` asks them instead of asserting them.
