# Limitations — what this package does not prove

### 1. The scope is one correction, and the head is not a candidate for acceptance

This head carries the refused-prefix state to the reader, closes the
exported claim boundary, completes the four terminal vectors, and corrects
the package protocol — and nothing else. `UNRESOLVED-BLOCKERS.md` lists
what stays open. A review of this package can accept the presentation
closure at most; it cannot accept E1, and the package claims nothing wider.

### 2. The sink proved is the harness's fetch seam

The request journals come from the replay harness's stubbed `fetch` — the
same seam, driven the same way, that the V7–V9 reviews used to prove their
defects. The prewarmed and genuinely late scenarios exercise the production
path-keyed body cache and the real deferred completion through that seam,
and the new ownership journal and `history.state` capture are projections
of that same shim. That is a claim about which addresses the production
files hand to the network boundary, when, and under which step; it is not a
network capture from a real browser session. The browser gate did run in
real Chromium at both ends, over the built site, but it asserts the shared
shell's generic contract, not this route's request journal.

### 3. No screenshots, and no route-specific Chromium probe

The stylesheet and markup are byte-identical to the parent; the visible
change is one terminal sentence on adversarial fixtures, and the sentence
itself is pinned byte-exactly in the replay against the model's export. A
raster of any real-corpus chapter would be identical at both ends because
the real corpus is entirely present-valid. What replaces a probe is the
head test file replayed against the parent's production files
(`logs/10-head-tests-against-parent.log`) and the two request journals side
by side.

### 4. The refused row's machine-readable surface is the sentence

The refused row shares the muted `missing` style hook with genuine absence;
the distinction a reader receives is the sentence, and the distinction a
machine receives is the sentence plus the projected `text_refused` field.
No `data-state` token or dedicated class was added — the page's ceiling has
13 gzipped bytes of headroom — and `REVIEW_REQUEST.md` §5 asks whether one
is wanted rather than assuming.

### 5. The parent-side battery baselines are inherited, not adjudicated

Full discovery, the make targets and the browser gate fail at the parent
and at the head in the same inherited identities; the head's post-record
run additionally fails the web-editions staleness target that any
`PROJECT-WORK.md` edit makes stale. The package proves the sets match under
the named volatile exclusions, not that the sets are acceptable. They
belong to their separate owners, and every such figure is labelled
inherited, never baseline, in `DERIVED-CLAIMS.md`.

### 6. The parent decomposition includes an infrastructure fault, stated apart

The head's test file pins the model by digest, so at the parent it fails
the byte-identity guard as well as the behavioral methods. The
decomposition in `DERIVED-CLAIMS.md` is derived from the log and reported
as methods run, controls passing at the parent, and failing subtest
identities — the guard's expected failure named apart from the methods that
state the defect.

### 7. Judgements are not derivations

Every figure a machine could derive is derived into `claims.json`. Whether
the refused sentence is truthful enough, whether classified-closed is the
right disposition for unproducible claim shapes, whether the pinned focus
values are the right expected values, and whether the model needs a ceiling
are judgements; `REVIEW_REQUEST.md` asks them instead of asserting them.
