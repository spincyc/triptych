# Visual Artifact Evaluation

## Your task

You are a fresh visual evaluator. The mechanical gates have passed. Now
evaluate every rendered page of both the canonical and synthesis PDFs for
visual quality. Do not rediscover what mechanical gates already checked
(build success, PDF existence, undefined references).

## Evaluation criteria

Inspect every rendered page and return structured findings covering:

1. **Crowding**: Is any page too dense to read comfortably?
2. **Weak hierarchy**: Are headings, sections, and body text visually
   distinguishable?
3. **Broken page rhythm**: Do page breaks disrupt the reading flow?
4. **Poor line lengths**: Are lines too long or too short for comfortable
   reading?
5. **Bad table or callout breaks**: Are tables or callout boxes split across
   pages inappropriately?
6. **Stranded headings**: Is a heading at the bottom of a page with its
   content on the next?
7. **Sparse spill pages**: Is a page nearly empty with only a few lines?
8. **Illegibly compressed fixed-pagination sections**: Is the Scriptural Date
   and Location page (page 2) or the two-page Themes and Movement section
   compressed to the point of illegibility?
9. **Clipping**: Is any text or image cut off at page margins?
10. **Bad terminal apparatus**: Are references, metadata, or scope sections
    poorly formatted or broken?
11. **Other visible defects**: Any other visual defect defined by current
    Triptych guidance in `guidance/editorial.md` or
    `guidance/repository.md`.

## Lane scope

This stage is a fan-out stage: the criteria above are partitioned across
the workflow's evaluation lanes, and the lane fragment that follows names
exactly which of them you own. Report findings for your own criteria only.
Another lane owns each of the others, and tpt joins every lane's findings
itself.

## Inspection method

1. Use the review rasters generated by `tools/tpt pdf-review`.
2. Open every full-size page raster. Do not rely on thumbnails alone.
3. Inspect both the canonical and synthesis PDFs.
4. The reviewed artifact must be the same artifact eventually accepted.

## Result

Return an evaluator result:
- `PASS` if no blocking visual findings.
- `CHANGES_REQUIRED` with blocking findings for any visual defect.
- `BLOCKED` if a visual defect cannot be resolved by revision.

Finding IDs must use the `VIS-` prefix and be stable across iterations.
