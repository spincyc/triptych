# /revise

Revise any existing collection document without replacing its governing genre, evidence contract, canonical shared sources, or publication discipline with a generic workflow.

## What to provide

The user's complete invocation context is:

$ARGUMENTS

Treat all of it as controlling input, whether it follows the suggestions below or is entirely free-form.

- The title, source path, PDF path, catalog row, or unambiguous description of the target.
- The requested correction, expansion, deletion, restructuring, renaming, or re-evaluation and the outcome that should remain true.
- Relevant sources, evidence concerns, currentness date, comparisons, desired emphases, and known affected consumers.
- Whether structural moves, installed PDFs, catalog changes, commits, or history rewriting are authorized, plus all free-form context, guides, exclusions, limits, and staging instructions.

## Preflight

1. Apply `commands/_conventions.md`, identify the target’s actual genre, and read every applicable profile completely.
2. Inspect the target source, research records, generation metadata, Makefile dependencies, installed artifact, README row, imports, consumers, and current worktree changes.
3. Determine whether the request changes a project convention; if so, update the correct universal or genre guidance in the same stage.
4. Establish the authority, edition, jurisdiction, calendar, language, and as-of facts that the requested revision makes material.

## Plan

State the requested outcome, exact source owners, evidence to re-check, research and metadata records to change, all affected consumers and artifacts, convention updates, verification gates, and authorized commit boundary.

## Commands

1. Edit the authoritative source rather than a generated PDF, build artifact, derived companion, or drifting copy.
2. Preserve unrelated user changes and the document’s established genre architecture except where the invocation deliberately changes it.
3. Re-evaluate every claim materially affected by the change, including downstream conclusions, cross-references, tables, timelines, indexes, appendices, source audits, scope records, and currentness statements.
4. Keep verified source text, source-grounded synthesis, project proposals, and unresolved evidence distinct. Record sources actually used and rejected leads where the governing profile requires them.
5. Refresh generation metadata for substantive generation, update all affected canonical fragments and consumers, and keep the README’s separate artifact columns coherent.
6. Build and inspect every affected document, install only reviewed PDFs, and commit only the coherent authorized stage with the required `AI summary:` body.

## Verification

Run the controlling profile’s complete gates, then check for stale terminology, duplicate text, broken imports and links, mismatched catalogs, incomplete metadata, unrebuilt consumers, layout regressions, and installed/build differences.

## Summary

Report the revision outcome first, then the authoritative files and records changed, affected consumers and PDFs, verification and authorized commit, and any limitation or deliberately deferred issue.

## Next Steps

Name only the one remaining review or follow-on change that is materially useful and outside the completed scope.
